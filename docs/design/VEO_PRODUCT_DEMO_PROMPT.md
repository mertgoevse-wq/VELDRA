# VELDRA Product Demo — Veo Production Prompt

This is a generation specification, not a claim that a video exists. VELDRA's approved brand mark and real product screenshots/assets must be supplied as references when available; Veo must not invent a replacement logo.

## Creative direction

Create a restrained, cinematic product demonstration of **VELDRA — an AI engineering workspace for web, desktop, and Android**. The interface is a serious technical workstation: deep navy/obsidian surfaces, sky-blue signal accents, crisp Inter UI text, Space Grotesk display text, and JetBrains Mono code/terminal text. Use precise geometry, thin borders, controlled depth, and a subtle technical grid. Avoid generic AI-chat imagery, excessive glassmorphism, neon gradients, organic blobs, fake code that dominates the frame, or unreadable microcopy.

The final product UI should look like the real VELDRA application. Use short UI close-ups with large, legible labels rather than pretending that generated video can render long source files accurately.

## Format

- Master: 16:9, 4K, 24 or 30 fps, 20–24 seconds.
- Keep the important UI and brand mark inside a centered 16:9 safe zone so a 9:16 crop remains usable.
- Camera movement is smooth and deliberate: gentle push-ins, lateral panel reveals, and one controlled pull-back.
- Motion language: short, purposeful transitions with a smooth cubic ease; no constant pulsing or camera shake.
- Audio: quiet technical ambience, tactile key clicks, restrained data pings, and a clean final resolve. No dramatic cyberpunk impacts.

## Shot list

### 1. VELDRA opens — 0:00–0:03
A dark navy canvas resolves into a subtle technical grid. The approved VELDRA mark (the V merged with a cursor and sky-blue sparkle) appears exactly as supplied, with a restrained edge highlight. The word `VELDRA` types in beneath it. Hold long enough for the silhouette to read.

### 2. Workspace initialization — 0:03–0:06
The landing workspace opens. The chat column, file/workbench region, and concise controls settle into place. A project brief opens with fields for platform, visual style, integrations, and offline requirements. Show the user choosing a small web project without inventing settings that are not present in the reference UI.

### 3. Agent activity — 0:06–0:09
The user sends a request. A compact `background tasks active` activity disclosure appears below the composer. Two task rows show a model, delegated task, running state, and elapsed time. One row completes and opens to show a short result. The visualization should communicate observability, not expose private chain-of-thought.

### 4. Code and workbench — 0:09–0:13
The workbench opens to the editor. A file tree, syntax-highlighted code, diff state, and preview are shown in clean cuts. Use short, deliberately authored snippets and large enough type to remain legible. Show a file change becoming a diff, then the preview updating.

### 5. Terminal execution — 0:13–0:16
Show the terminal only in a configured capable runtime or as a clearly labeled Remote Runtime command-profile panel. Display a safe command profile and streamed output; do not show arbitrary shell input or imply that Android fallback mode can execute local commands.

### 6. Skin switch — 0:16–0:18
Open Settings and switch from `VELDRA Core` to `Matrix` or `Midnight`. Show the entire workspace changing through a short, calm theme transition. The setting must visibly preserve hierarchy and contrast; do not use a flashy color wash.

### 7. Result and deployment — 0:18–0:21
Show a successful preview/result state and a concise deployment or export affordance only if it is present in the supplied product capture. Avoid fabricated provider confirmations, URLs, analytics, or production claims.

### 8. Final lockup — 0:21–0:24
Pull back to the balanced workspace, then resolve to the supplied VELDRA mark and the line `Build with intent.` on deep navy. Hold for at least 1.5 seconds. End cleanly; no watermark and no invented partner logos.
